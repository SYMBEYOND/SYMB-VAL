## SYMB-VAL orientation

SYMB-VAL is a lightweight cognitive checkpoint intended to keep fast pattern recognition from becoming false certainty. Its current v0.1 form is a manual tool that asks the operator to state a claim, belief basis, failure condition, verification need, confidence, and status.

The repository defines four validation states: assumed, tested, verified, and rejected. These are workflow labels whose meaning depends on the evidence actually supplied; the labels are not self-validating.

Important distinctions and boundaries:

- v0.1 is the current manual checkpoint tool. Token integration, index integration, automatic AI triggering, and ecosystem-wide integration are documented as planned, future, or vision work.
- A `verified` label should only be used when the claim has actually been confirmed through reliable evidence or direct testing; SYMB-VAL does not make a claim true merely by formatting it.
- The tool supplements judgment and verification; it does not replace external research, source checking, testing, or domain expertise.
- Examples and future architecture illustrate intended use and do not establish that those integrations are already implemented.
- ReBoot maintenance does not authorize changes to validation semantics, shell tooling, integration architecture, product behavior, or licensing.
- No repository paths or commands are human-approved through ReBoot yet.
